# 課堂搶答系統：共同需求基準（草稿 v0.7）

> 用途：SpecKit 組與 OpenSpec 組共用的需求來源。兩組的 spec 都引用這裡的編號（R、E、Q、D），確保兩個系統功能一致。
> 狀態：草稿，需大組 4 人確認後才可定稿。之後任何修改都要記在文末「變更紀錄」，並通知另一組。
> 範圍：核心功能、題組、CSV、公平機制、大螢幕結果頁，以及兩組共同支援的 Q8 `{{答}}` 標記。E4-1 判錯遞補、E4-2 倒數計時、E4-4 `.xlsx` 備援延期，本次不列入驗收。

---

## 1. 角色

| 角色 | 說明 |
|---|---|
| 老師 | 匯入題目、建立活動、開始/結束搶答、檢視作答狀況與結果、匯出 |
| 學生 | 以「組」為單位作答；同一組可以有多位學生同時登入 |
| 大螢幕 | 唯讀畫面，給教室投影用，不需登入 |

---

## 2. 核心需求（必做）

| 編號 | 需求 | 驗收條件 |
|---|---|---|
| R1 | 系統有老師與學生兩種使用者 | 老師頁面需輸入老師 PIN；學生頁面看不到任何老師控制項 |
| R2 | 老師可匯入 Guided Notes 題目 | 輸入 Google 試算表網址後，系統列出偵測到的題目；**題數與試算表一致**；只需題號，題目敘述可選擇性擷取 |
| R3 | 老師可開啟、結束搶答 | 「開始」後學生才能作答；「結束」後所有提交一律拒收 |
| R4 | 老師可檢視作答狀況與結果 | 搶答中即時看到「每題 × 每組」是否已送出、送出順位與答案；結束後看到每題成功組 |
| R5 | 老師可把成功組答案匯出到原 Guided Notes | 答案寫進原試算表每題的填空格；不寫死任何儲存格位置；助教換一份表也要正確 |
| R6 | 學生在搶答開始後作答 | 未開始時只看到等待畫面；開始後出現題目與輸入框 |
| R7 | 學生以組為單位送出答案 | 同組任何一人送出即代表全組；同組其他成員畫面同步顯示「已送出」 |
| R8 | 學生在結束後檢視結果 | 結束後學生畫面自動切換到結果；學生與大螢幕的結果畫面每題顯示成功組與它的答案，其他組只顯示順位、不顯示答案（老師的結果頁顯示全部組的答案） |
| R9 | 結束前看不到其他組作答狀況 | **伺服器**在結束前不得把其他組的任何作答資料送給學生端（不只是前端隱藏）；本組的順位與是否成功也不送，因為會透露其他組的狀況 |
| R10 | 最快搶答的組別為成功答案 | 先後以伺服器收到的順序判定，不採用客戶端時間 |
| R11 | 同步所有使用者的活動階段 | 老師切換階段後，所有已開啟的頁面在 1 秒內切換；重新整理或中途加入也顯示目前階段 |

## 3. 額外需求（方案二範圍）

| 編號 | 需求 | 驗收條件 |
|---|---|---|
| E1 | 匯入題組 | 題組內所有小題必須一起填完、一起送出；只填一部分時不能送出 |
| E2 | 匯出活動結果 CSV | 欄位至少含：題號、小題、組別、答案、原始順位、最終順位、是否成功、送出時間、說明；用 Excel 開啟中文不亂碼（UTF-8 含 BOM）；以「=」「+」「-」「@」開頭的答案不會被 Excel 當成公式；送出時間以台灣時間（UTC+8）顯示到秒 |
| E3 | 更公平的搶答順位機制 | 老師在建立活動時或「準備中」選擇規則：「純速度」（預設）或「均分上限」（見 D7），開始後不能更改；結果頁顯示原始順位、最終順位與說明：最終順位是該題沒有被跳過的提交依序號排列的順位，被跳過的提交沒有最終順位；說明寫出跳過原因（例如「第 1 組已達上限 2 題」）或遞補原因（例如「遞補：第 1 組已達上限」） |
| E4-3 | 大螢幕結果頁 | 唯讀頁面，適合投影：搶答中顯示「已送出組數」（不顯示答案，也不顯示是哪幾組送出）；結束後顯示每題成功組與答案 |

## 4. Guided Notes 解析與回寫規則（Q 系列）

依官方範本：表頭列有「題號」「題目」「作答」；B 欄題號、C 欄題目、G:H 欄作答（表頭「作答」為 G4:H4 合併）；題與題之間有空白列；題組的後續小題 B 欄為空，G 欄預填「（1）」「（2）」標籤，右邊的 H 欄是空白的作答框。**但系統不得假設上述欄位與列號固定。**

實際下載兩份範本的 .xlsx 檢查後（2026-10-21）另有以下細節：工作表名稱為「學習單」；題號存成數值（讀出來是 `1.0`，不是文字 `1`）；題目格為 C:F 合併、單題的作答格為 G:H 合併；題組的題號格上下合併（例如 B5:B6），小題那一列讀到的題號是空值；題組小題的 G 欄（欄寬 8、置中）只放標籤，沒有和 H 合併，答案應寫在右邊較寬的 H 欄（欄寬 24）；題與題之間的空白列在單題範本是整列 B:H 合併，在題組範本則沒有合併。

| 編號 | 規則 |
|---|---|
| Q1 | 掃描工作表前 20 列，找出同時包含「題號」與「作答」關鍵字的列作為表頭列（關鍵字比對前先去除空白、統一全半形；關鍵字清單可設定） |
| Q2 | 由表頭列得到題號欄、題目欄（可無）、作答範圍；作答範圍是「作答」表頭格涵蓋的欄，表頭格是合併儲存格時包含整個合併範圍（官方範本為 G:H） |
| Q3 | 表頭以下逐列掃描：題號欄有值 → 新的一題；題號欄空（或與上一列的題號屬於同一個合併儲存格）但題目欄或作答欄有內容 → 上一題的下一個小題；整列空白（含整列合併的空白格）→ 略過 |
| Q4 | 題號正規化：接受數值儲存格（如 `1.0`）與 `1`、`1.`、`１`、`Q1`、`第1題` 等文字寫法，統一為整數 |
| Q5 | 每個小題記錄作答格座標（工作表名稱 + 列 + 欄）；作答格為合併儲存格時取左上角；有標籤格時同時記錄標籤格座標（Q7） |
| Q6 | 一題只有一個作答格為「單題」，兩個以上為「題組」 |
| Q7 | 作答範圍第一欄的格子內容是「（n）」時，該格是「標籤格」，n 視為小題編號；作答格是同一列、標籤格右邊、仍在作答範圍內、不屬於標籤格合併範圍的第一個空白格；這些格子都已有內容時取第一格，並在匯入預覽顯示警告。匯出只寫作答格，標籤格不動。標籤格右邊沒有這樣的格子（作答範圍只有一欄，或標籤格的合併範圍已涵蓋整個作答範圍）時，作答格就是標籤格，匯出寫成「（1）答案」 |
| Q8 | 顯式標記（兩組共同支援）：比對前統一全形與半形並去除空白；若任何作答格含 `{{答}}`，則以含標記的格子作為作答格，題號仍依 Q3 歸屬；匯出時以答案取代標記。小題標籤取自標記格開頭的「（n）」，沒有時取同一列的標籤格（Q7），所以在官方題組範本的 H 欄放標記，結果與不放標記相同 |
| Q9 | 匯入後先顯示預覽（總題數、單題/題組、每個小題的作答格位置、警告），老師確認後才建立題目集 |
| Q10 | 錯誤要有清楚訊息：網址無效、沒有權限（同時顯示需共享的服務帳號 email）、找不到表頭、0 題、題號重複 |
| Q11 | 匯出前重新讀取試算表並重新定位，若題號或作答格位置與匯入時不同，停止匯出並說明原因 |
| Q12 | 匯出只寫作答格，不更動其他儲存格；答案一律以文字寫入，以「=」「+」「-」「@」開頭或看起來像數字、日期的答案也不轉成公式、數字或日期；寫入前把原值備份在本機（伺服器重新啟動後仍保留），可一鍵還原；同一個活動匯出多次時，還原回到第一次匯出前的原值；匯出需要服務帳號有「編輯者」權限（匯入只需要「檢視者」） |
| Q13 | 沒有任何組成功的題目，作答格保持原狀 |

## 5. 設計決策（D 系列）

| 編號 | 決策 |
|---|---|
| D1 | **整份開放**：老師按「開始」後所有題目同時開放，各組可按任意順序作答；每題各自判定成功組 |
| D2 | 階段：準備中 → 搶答中 → 已結束；只有老師能切換；不可從「已結束」回到「搶答中」 |
| D3 | 每組每題只接受**第一筆**送出，送出後不能修改；空白答案（只有空白字元也算）拒收；單一答案上限 200 字，題組的每個小題各自計算，看得到的字元不論全形、半形都算 1 個字；答案在檢查、保存與匯出前只去掉前後的空白字元（包含全形空白與換行），中間的空白、全形半形與換行都保持學生送出的原樣；事件紀錄另外保留送出時的原文 |
| D4 | 先後判定：伺服器收到時給遞增序號；同組兩人同時送出只接受先到的一筆 |
| D5 | 學生加入方式：輸入活動代碼並選擇組別；身分存在各分頁自己的工作階段中，所以同一個瀏覽器開多個分頁可以模擬不同組；學生可以「離開活動」，回到輸入代碼的畫面 |
| D6 | 組數與組名由老師在建立活動時設定（預設 4 組：第 1 組～第 4 組）；組數可設 2～10 組，超出範圍時拒絕建立並說明；老師的活動畫面顯示各組目前線上的學生頁面數 |
| D7 | 均分上限：每組在本次活動最多成功 ⌈題數 ÷ 組數⌉ 題（題數是活動的總題數，題組算 1 題，沒有人作答的題目也算；組數比題數多時上限是 1）；依伺服器序號由小到大**逐筆**處理被接受的提交（不是逐題處理）：該題還沒有成功組、而且送出的組還沒達上限，該組就成為成功組；達上限後該組的提交仍記錄順位，但被跳過，成功資格由下一順位遞補；某題所有提交都被跳過時，該題沒有成功組 |
| D8 | 學生端預設只顯示題號；老師可開啟「顯示題目敘述」 |
| D9 | 憑證：Google 服務帳號金鑰放在 repo 以外，透過環境變數指定；repo 只放範例設定檔 |
| D10 | 全部在本機執行，一個指令啟動，用多個瀏覽器視窗模擬老師與各組 |
| D11 | 預留擴充點：排名規則可替換、活動以「回合」組織題目、保存完整提交事件紀錄、答案正規化函式（為方案三準備） |
| D12 | 活動保存在本機檔案；伺服器重新啟動後保留所有活動，並回到重新啟動前的階段，學生重新連線即可繼續 |

## 7. 測試用 Guided Notes

| 名稱 | 內容 | 目的 |
|---|---|---|
| T1 | 官方單題範本（6 題） | 基本情況 |
| T2 | 官方題組 + 單題範本（4 題，其中 2 題為題組） | 題組辨識 |
| T3 | T2 的內容，表頭移到第 2 列、整張表右移一欄（題號在 C 欄、作答在 H 欄） | 證明沒有寫死位置 |
| T4 | 12 題，含 3 個小題與 2 個小題的題組，題與題之間沒有空白列，部分題號寫成文字（`4`、`5.`、`６`、`Q7`、`第8題`） | 泛化、題號正規化（Q4） |
| T5 | 兩份：缺少表頭／題號重複 | 錯誤訊息 |
| T6 | T2 的副本，在每個作答格放入 `{{答}}` 標記 | 驗證 Q8；解析題數、題型、作答格與標籤應與 T2 相同 |

每份都在 Google 試算表建一份，也放一份 .xlsx 在兩個 repo 的測試資料夾。.xlsx 檔與每份的預期解析結果（題數、每個小題的作答格位置）見 `tests/fixtures/guided-notes/README.md`。
