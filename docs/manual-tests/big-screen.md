以下由自動測試涵蓋（`npm test` 155 項通過）：
- 大螢幕在搶答中經 HTTP 與 Socket 收到的資料，結構上不含答案、組別送出明細、順位或成敗（`公開大螢幕頁與 HTTP 狀態端點只提供階段白名單`、`screen socket is read-only and buzzing payloads omit all submission details`），與第 2b 列的人工觀察一致。
- 大螢幕連線送出改變狀態的事件一律被拒。
- 學生視圖在搶答中仍不含任何他組資訊與順位（R9）；他組送出時本組不收到推播。
- 均分上限下被跳過的組在結果中顯示「已達上限（跳過）」而不顯示最終順位。
- 結束後本組未成功時，學生仍可看到本組答案，但看不到其他非成功組的答案。

## 實作過程發現的問題

1. **R8 新增「其他組順位」後，既有 R9 測試的結束後預期需更新。**（已處理）新增 `otherSubmissions`（只含組別與原始順位、跳過狀態，不含答案）後，4 個既有測試的結束後比對失敗。確認欄位不含答案後，只更新結束後的預期，搶答中的 R9 斷言維持不變，並新增「非成功組答案不出現在任何欄位」的斷言。
2. **結束後學生看不到自己組的答案。**（提交前已修正）更新上項時，需求被理解為「非成功組（包含本組）的答案都不顯示」，導致本組未成功時「查看本組答案」也被隱去，違反已封存的 live-buzzer 規格。審查 Codex 回報時發現，恢復本組答案欄位並恢復 ui-polish 的相關斷言，另加回歸測試。
