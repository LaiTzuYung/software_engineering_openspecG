# Design

## Context

目前 `SpreadsheetExportPreviewService` 將每次成功寫入的原值與寫入值存成獨立 JSON；`restoreLatest` 選最新成功檔，只還原仍等於該次寫入值的格，並在寫入後重讀。教師端目前只有立即執行的 `/api/teacher/export/restore`，頁面單一按鈕直接呼叫該路由。Q7 parser 在沒有右側候選格時會將標籤格同時作為作答格；預覽組值時，非標記模式目前只使用答案字串。

## Goals / Non-Goals

**Goals:**

- 讓逐格首次原值與活動識別永久存於 `data/`，並從歷史回寫紀錄計算最後系統寫入值。
- 讓還原預覽快照綁定活動與來源，確認時完整比對，避免過期預覽寫入。
- 讓 Q7 邊界格的答案保留實際標籤文字格式，並使用同一份首次原值還原。

**Non-Goals:**

- 不更動其他活動階段、題組定位或回寫預覽的結構驗證規則。
- 不清除已還原活動的原值資料，也不把試算表內容同步保存到伺服器記憶體作為唯一來源。
- 不為 XLSX 匯入增加線上試算表還原能力。

## Decisions

### 維持既有 JSON 回寫紀錄並以活動/座標聚合首次原值

延用 `data/spreadsheet-export-backups/` 的本機 JSON 持久化及 `activityCode`、spreadsheet ID、gid、目標座標等欄位。讀取活動紀錄時逐格保留首次成功寫入前的 `originalValue`，並取該格最新成功紀錄的 `writtenValue` 作為「系統最後一次寫入值」。同一格的後續備份仍保有第一次 `originalValue`，載入時以時間排序及前值鏈檢查避免後續備份覆蓋初值；失敗紀錄不更新最後成功值。每次回寫仍保留獨立 JSON，以保留寫入前備份與失敗狀態。

**舊備份相容：**`restore-first` 前的單次成功備份已含 `status`、`spreadsheetId`、`gid`、`activityCode`、`targets[].originalValue` 與 `targets[].writtenValue`，可直接視為該活動各格的第一次成功寫入記錄，不需轉檔。備份只在老師要求還原預覽時惰性讀取，不在伺服器啟動時載入；目錄不存在、JSON 無效、欄位缺漏或格式不符的檔案會被略過，不得使啟動或還原流程崩潰。成功且必要欄位完整的舊檔繼續參與逐格聚合。

**替代方案：**新增一份活動快照索引檔。索引可加快查找，但需處理回寫 JSON 與索引之間的雙檔一致性；目前資料量及本機 JSON 模式適合由成功紀錄聚合，故不增加第二個持久化真相來源。

### 還原預覽保留不可變快照並在確認時全量比對

新增還原預覽資料，包含活動/試算表識別、逐格 A1、當前內容、原值、最後系統寫入值及預覽時內容快照。狀態只供老師判讀：內容等於最後系統寫入值顯示「將還原」，否則顯示「已被手動修改」。確認先重新讀取所有目標格；任一內容與快照不同即整批中止，預覽 ID 作廢且要求重預覽。快照一致時無論狀態均寫回原值，完成後重讀每格並區分已還原與失敗。

**替代方案：**確認時只比較目前值與預覽讀取值相同的格、並跳過手動修改格。這會違反老師已明確確認整份清單的語意；故手動修改格仍列在預覽，確認後一併還原。

### 以兩個明確還原端點延續教師頁面控制

保留目前 `POST /api/teacher/export/restore` 作為「還原預覽」入口，新增確認入口（例如 `POST /api/teacher/export/restore/confirm`，帶預覽識別碼）。頁面保留 `export-restore-button` id 並將文字改為「還原預覽」；點擊後顯示格子表格和獨立「確認還原」按鈕，兩個狀態以不同顏色標示，確認後呈現逐格成功/失敗。端點命名在實作時與既有路由慣例一致，但不可讓舊入口直接寫入。

**替代方案：**沿用一個端點以請求欄位切換預覽/確認。分開端點使讀取型預覽與具副作用確認的意圖明確，也較容易單獨測試，故採兩端點。

### Q7 標籤退回格組值直接由目前標籤文字加答案

當解析結果的 `labelCell` 與 `answerCell` 為同一儲存格，回寫預覽將該格目前文字（例如 `(1)` 或 `（1）`）接上答案；其他格維持目前答案或標記替換流程。原標籤文字作為目標格首次原值持久保存，還原不從目前解析文字推導，避免答案回寫後失去標籤格式。標記模式原值是包含 `{{答}}` 的完整匯入原文；多次回寫與還原均沿用此原值。

**替代方案：**依小題編號重建統一使用全形括號的標籤。這會把原本半形或其他可接受格式正規化，故直接保留試算表目前文字。

## Risks / Trade-offs

- [舊備份可能含無效 JSON 或缺漏欄位] → 還原時逐檔驗證必要欄位並略過不合格式的紀錄；啟動不掃描備份目錄。合法的舊單次備份保留原格式直接讀取。
- [活動代碼可能重複或資料夾含多活動同一試算表紀錄] → 聚合鍵同時使用 activityCode、spreadsheetId、gid 及工作表/A1 座標。
- [試算表在全量重讀之後、批次寫入之前仍可能被外部修改] → 確認時使用 Sheets 批次寫入並盡量縮小比對到寫入的間隔；Google Sheets API 若不提供跨讀寫交易，設計無法消除該極短競爭窗口，重讀驗證將揭露寫入後不符原值的格。
- [標籤格原值為空值或非文字型別] → Q7 同格情境需以實際辨識到的標籤文字格式組字；備份仍保存原始型別，還原空值沿用既有以空字串清空並視空白等價驗證的行為。

## Migration Plan

不需變更既有備份檔案格式或清除資料。舊版成功回寫 JSON 可直接作為活動逐格首次原值與最後寫入值的來源；不做啟動時轉檔或 eager scan，還原預覽才按檔案讀取，無效或缺欄位檔案略過。標記模式還原使用成功備份中的完整 `originalValue`（例如 `答：{{答}}`），不從當前答案格反推。更新 API 與頁面後，原預覽按鈕仍用 `export-restore-button`，文字為「還原預覽」，新增「確認還原」按鈕；舊立即還原行為移除。回退程式版本時既有獨立 JSON 備份仍可讀。
