# Design

## Context

目前 repo 沒有應用程式碼或既有 capability spec；專案含共同需求基準 v0.4 與六份 Guided Notes `.xlsx` fixtures。需求與驗收契約見 `proposal.md` 及 `specs/guided-notes-import/spec.md`。本設計採 TypeScript（Node.js）作為規劃預設，尚需與 SpecKit 組對齊。

## Goals / Non-Goals

**Goals:**

- 讓解析器只依賴統一的格狀資料，不依賴 Google Sheets API 或 XLSX 函式庫的資料結構。
- 以 Google Sheets API 讀取線上試算表，並以相同解析器處理 fixture `.xlsx`。
- 讓解析定位依據表頭、合併範圍與資料內容，能處理欄列位移。
- 在題目集建立前提供可確認的解析結果與警告。

**Non-Goals:**

- 不實作答案回寫、匯出前重新定位、備份或還原；Q11～Q13 留給後續匯出 change。
- 不實作 Q8 `{{答}}` 標記；只保留未來擴充解析策略的邊界。
- 不在解析器中呼叫 Google API 或讀取 XLSX 檔案。

## Decisions

### 格狀資料與來源轉接器

解析器輸入採來源無關的格狀資料：工作表名稱、儲存格值及其合併範圍。資料轉接器負責將來源格式轉成該模型；解析器輸出題目、題組、小題、作答格／標籤格座標與警告。座標至少能保留工作表名稱及列欄位置，呈現時可轉為 A1 格式。

提供兩種轉接器：

- Google Sheets API 轉接器是老師線上匯入主流程，讀取試算表中工作表格值與合併範圍，不先下載或轉換成 `.xlsx`。
- `.xlsx` 轉接器只用於離線 fixture 自動測試與需求指定的備援；它產生同一格狀資料模型，重用同一解析器。

替代方案是分別為 Google 與 XLSX 寫解析器；不採用，因為兩套解析可能在合併儲存格或題組處理上分歧，fixtures 也無法直接驗證線上主流程所用解析規則。

### 試算表網址與工作表選擇

網址解析器驗證支援的 Google 試算表網址形式，抽出 spreadsheet ID 與選用的 `gid`；無法辨識的主機、路徑或缺少 ID 均回報明確網址錯誤。線上轉接器按 ID 讀取試算表 metadata 與格資料：指定 `gid` 時選取對應工作表，否則使用 metadata 中第一張工作表。無效或不存在的 `gid` 以清楚錯誤回報。

讀取格值時使用 Google Sheets API 的 `UNFORMATTED_VALUE` 格式選項，取得數值而非依儲存格顯示格式產生的文字；解析器保留數值型別並按數值題號規則正規化。例如線上儲存格數值 1 與 XLSX 轉接器讀出的數值 1 均解析為整數題號 1，避免格式化字串差異造成解析結果不同。若 API 使用 `GridData` 讀取，轉接器需以 `effectiveValue` 的數值內容映射相同模型。

替代方案是讓使用者另外輸入工作表名稱；本 change 依需求以網址中的 `gid` 選擇，免增輸入欄位。

### 題目集暫存與儲存

題目集建立前，解析結果只留在記憶體中的預覽狀態；老師確認後，題目集暫定存入記憶體並序列化為 JSON 檔，路徑置於 repo 的 `data/guided-notes/`。此目錄須加入 repo `.gitignore`，避免匯入的題目資料被提交。記憶體提供目前執行中的快速讀取，JSON 檔提供本機保存；兩者同步失敗時需回報建立失敗，避免畫面與磁碟資料不一致。此儲存方式與目錄命名仍列為待與 SpecKit 組對齊的暫定決策。

替代方案是只使用記憶體；不採用作為暫定方案，因為程式重啟後題目集會消失。另一方案是使用資料庫；本 change 暫不引入資料庫，以降低初始儲存需求。

### 動態解析流程

解析器依序：掃描前 20 列並正規化表頭文字；以「題號」及「作答」欄定位資料範圍；使用作答表頭的合併範圍決定作答欄範圍；再逐列追蹤目前題目，處理題號合併與空白列；正規化題號、檢查重複；依作答範圍判斷標籤格、作答格及合併格左上角座標；最後依小題數分類單題／題組並產出預覽資料。解析器不應以範例中的 B、C、G:H 或指定列號作為條件。

題號正規化應先統一全半形，再接受數值整數表示與 `1`、`1.`、`１`、`Q1`、`第1題` 等形式；不能解析的非空題號使整份匯入失敗並包含來源座標。重複題號錯誤列出重複位置。

替代方案是掃描固定範本位置；不採用，因 T3 特意位移表頭與欄位，且助教會以不同格式測試。

### 匯入預覽與建立邊界

解析成功只產生暫存預覽資料，不立即新增題目集。預覽包含題數、類型、小題作答格與標籤格位置、警告；只有老師確認後才提交建立。解析錯誤或確認前離開流程均不建立題目集。題目敘述若可擷取，作為可選資料，不參與題號或題組判斷。

替代方案是解析成功即建立再允許刪除；不採用，因無法滿足確認前不得建立的需求，也會留下未確認資料。

### 憑證與環境設定

Google 服務帳號憑證檔案存於 repo 外，程式由環境變數取得路徑或必要設定；repo 不含金鑰。權限錯誤訊息從執行設定取得服務帳號 email，避免 email 寫死在程式或文件內。`.env.example`（若採用）只能列變數名稱與非機密範例值。

替代方案是把服務帳號金鑰放在 repo 的設定檔；不採用，避免憑證外洩。

### Q8 擴充點

本 change 不解讀 `{{答}}`，也不以標記覆寫 Q7 的作答格判定。格狀資料保留原始儲存格值，解析流程將作答格判定設計為可替換／擴充的獨立步驟，未來若 SpecKit 確認支援 Q8，可新增策略及測試，不改動來源轉接器介面。

## 待與 SpecKit 組對齊

以下是本次規劃採用的暫定預設，需兩組對齊後再視結果調整規格；尚非共同需求基準已確認內容：

- 題目敘述欄存在時擷取；沒有題目欄時留空。
- 標籤格右方候選格都有內容時，取第一格、顯示警告，並允許老師繼續確認。
- 標籤右側沒有作答範圍內可用格時，作答格退回標籤格。
- 非空題號無法解析時，整份匯入失敗並指出題號格座標。
- 表頭下方沒有題目時，顯示「沒有偵測到題目」。
- 題目集確認後暫以記憶體加 JSON 檔保存，JSON 放在 repo 的 `data/guided-notes/`，並將該目錄加入 `.gitignore`；需確認是否符合兩組對持久化方式與路徑的共識。

## Risks / Trade-offs

- [Google Sheets API 回傳的合併範圍與 XLSX 函式庫資料表示不同] → 由兩個轉接器統一成同一格狀模型，並以相同 fixture 預期結果驗證解析器。
- [Google Sheets API 的合併範圍座標為 0 起算且結束索引不含在範圍內，exceljs 的合併範圍座標為 1 起算且包含結束位置] → 轉接器在輸出格狀模型前統一為同一座標慣例，並以 mock API 座標轉換測試與 XLSX 合併範圍測試驗證起始格、結束格及左上角一致。
- [服務帳號憑證環境變數缺漏或路徑錯誤] → 啟動／匯入時回報明確設定錯誤，文件說明憑證位置與環境變數，不輸出金鑰內容。
- [Google 試算表在預覽期間被修改] → 本 change 僅讀取與建立題目集，不回寫原表；匯出前重新定位及差異檢查屬 Q11 後續 change。
- [兩組對上述預設有不同理解] → 在實作前對齊「待與 SpecKit 組對齊」清單，並同步修訂 spec 與驗收案例。

## Migration Plan

此為新增匯入能力，沒有既有資料遷移。實作階段先加入格狀模型與離線解析測試，再接上 Google Sheets API；上線前以真實 Google 試算表逐份人工匯入 T1～T5，確認解析結果與 XLSX fixture 相同。若線上 API 流程未能通過驗收，可停用匯入入口並修正轉接器，不需回復既有資料。
