# Design

## Context

相關實作目前分布在共同解析器、老師／學生視圖、HTTP 與 Socket 傳輸及 CSV formatter。解析器遇到無法辨識的非空題號會丟出錯誤；首個有效題號前的內容也會失敗。老師視圖由 `createTeacherView` 建立，但目前沒有連線數。Socket 認證資料已區分 teacher、student、anonymous，學生視圖採明確欄位白名單。CSV 目前只輸出有提交的列，並只處理 CSV 引號與分隔符跳脫。

限制是維持 `tests/fixtures/guided-notes/README.md` 的 T1～T5 預期（特別是 T5 重複題號錯誤）、既有學生視圖及 R9 隔離、不改回寫邏輯。來源文件 `docs/共同需求基準.md` 實際標為草稿 v0.4；未找到獨立 SpecKit 組 001 規格，本 change 依使用者列明規則及 fixture 預期規劃。

## Goals / Non-Goals

**Goals:**

- 以警告和略過處理匯入中可局部復原的列錯誤，同時保留指定的整份失敗條件。
- 在老師專用視圖呈現可信的即時組別連線數。
- 產生可安全由試算表開啟、且能表示無人提交題目的 CSV。
- 為每個受影響行為提供自動測試及一份明確的人工測試流程。

**Non-Goals:**

- 改變 T1～T5 的解析結果、學生視圖或 R9 資料隔離。
- 改變試算表回寫定位、驗證、備份、寫入或還原流程。
- 將連線數持久化；服務重啟後連線數由當下 Socket 重新計算。

## Decisions

### 實際行為差異清單

以下「原行為」依目前 `src/` 實作檢視；「新行為」依本 change 規格。

| 項目 | 原行為 → 新行為 |
|---|---|
| 1. 無效題號 | 非空題號無法正規化即丟出整份匯入錯誤 → 略過該列及後續同題內容直到下一有效題號，並於預覽警告指出題號儲存格位置。找不到表頭、零題、重複題號維持整份失敗。 |
| 2. 首個有效題號前內容 | 有內容但沒有目前題目時丟出 `question-without-number` → 略過內容列並顯示位置警告。 |
| 3. 表頭同格 | 表頭掃描可在同一格先後命中「題號」和「作答」→ 必須由不同儲存格提供兩個表頭，同格不算。 |
| 4. 小題標籤 | 僅接受整格完全符合半形化後 `(<數字>)` 的內容 → 接受全／半形括號，括號內數字前後可有空白，並以開頭標籤數字為小題號，即使後續有文字。 |
| 5. 題號缺號 | 目前不檢查缺號 → 預覽警告缺少的正整數；仍照來源順序解析，不要求題號排序。 |
| 6. 活動組數 | `createActivityState` 僅拒絕 0 組或空白組名，組數沒有上限 → 限制 2～10 組；超界時 HTTP 建立活動請求回傳中文錯誤，不替換既有活動；預設四組不變。 |
| 7. 老師線上人數 | 老師視圖只有組名與送出狀態，沒有在線頁數 → 每組顯示當下已認證且連到該活動的學生 Socket 數，連線、斷線即推送老師更新；teacher-only view 承載此欄位，student view 不增加欄位。 |
| 8. CSV 防公式 | CSV 只處理逗號、引號及 CR/LF 欄位引用，未防公式 → 欄位字串若以 `=`, `+`, `-`, `@`, Tab、CR 或 LF 開頭，先加 `'` 再作 CSV quoting。 |
| 9. 無提交題目列 | 該題沒有提交時完全不輸出資料列 → 每題仍輸出一列：題號保留、組別／答案／原始及最終順位留空，說明為「沒有組別送出」。 |
| 10. CSV 送出時間 | 直接輸出伺服器記錄的 ISO 8601 UTC 時間（毫秒精度、`Z`）→ 僅在 CSV formatter 輸出時轉為台灣時間 UTC+8，格式 `YYYY-MM-DDTHH:mm:ss+08:00`，不含毫秒；內部提交時間維持原值。例如 `2026-11-27T13:47:01.559Z` → `2026-11-27T21:47:01+08:00`。 |

### 解析策略與錯誤範圍

解析器逐列維持「目前有效題目」與「正在略過的無效題號列」狀態。遇到無效題號時先產生含題號格座標的警告，接續列在下一個有效題號出現之前均不附加到前一有效題目；若無效題號本身位於第一題之前，也只保留無效題號警告，不重複把後續同題列判為前置散落內容。空白列仍略過。有效題號恢復解析並作為缺號掃描輸入。

缺號依解析出的題號集合計算「1 到最大題號」之間未出現的正整數，不依序列位置報錯。若題號順序為 1、4、2，沒有缺號；若為 1、2、4，警告缺 3。警告型別沿用預覽既有 `ParseWarning` 呈現方式，`cell` 指向觸發問題的題號格或前置內容列的相關儲存格，讓老師頁可以顯示工作表及 A1 位置。

表頭掃描仍使用現有關鍵字正規化和前 20 列範圍，但只有題號、作答欄位索引不同時才接受表頭。標籤解析以 Unicode 正規化後檢查字串開頭的括號數字，抽取數字後原封不動沿用現有標籤右側空白格定位、合併格左上角及警告規則。

### 老師專用 Socket 計數

以 Socket.IO 目前連線清單作為來源，依 `role === "student"`、活動代碼及已解析的 `groupId` 聚合數量。不要在活動狀態儲存計數，避免重複連線、斷線競態或程序重啟造成陳舊數值。建立一個可重用的計數／老師視圖建構邊界，讓 Socket 推播與認證 HTTP 老師活動端點都能取得一致資料。

在學生連線身分驗證完成後，向老師廣播新視圖；在 Socket `disconnect` 時重新聚合並廣播。斷線計算只納入仍連線的 Socket。提交、階段或敘述更新既有老師視圖推播也使用同一計數來源。學生資料仍只經 `createStudentView` 白名單輸出，絕不把 teacher view 或計數欄位共用到學生 payload。

### 組數驗證位置

在活動模型建立入口集中驗證 `groupNames.length` 為 2～10，使直接呼叫與 HTTP 建立均不能繞過限制；HTTP 邊界把範圍錯誤轉為中文 400 錯誤。先驗證再替換 `ActivityManager.current`，確保拒絕請求不會覆蓋正在使用的活動。空白組名仍維持現有中文拒絕規則。

### CSV 序列化

對每個欄位值先轉字串，檢查第一個字元是否屬指定危險前綴；符合時補單引號，再執行現有 CSV quoting。這同時保護答案與可由使用者提供的組名等欄位，而不是只處理答案。無提交佔位列每題一列，題號欄填題號，小題、組別、答案、順位與成功／送出時間欄留空，說明欄填指定文字；順位兩欄均視為空白。這可避免將一個無提交的題組展開成多列。

CSV 送出時間只在輸出邊界由伺服器保存的 UTC ISO 8601 字串轉換為 UTC+8，移除毫秒並附上 `+08:00`。提交紀錄及伺服器內部時間不修改。

### 測試策略

解析單元測試增加無效題號區段、首題前內容、同格表頭、標籤空白／尾字、缺號及不排序情境；既有 XLSX adapter fixture 測試確保 T1～T5 輸出預期不變、T5 仍失敗。活動測試覆蓋 1／2／10／11 組邊界與中文 HTTP 錯誤；Socket 測試驗證連線加入、離開與關閉後更新，以及學生事件 payload 中不存在人數欄位。CSV 單元測試涵蓋六種公式前綴、普通文字不變、CSV quoting 次序及無人提交列。

人工測試使用 T2 的新複本，不碰原始 fixture；加入無效題號區段、首個有效題號前的說明列、「( 1 )」標籤與題號缺口，確認解析預覽警告與原題位置。再以多個學生分頁加入／離開驗證老師在線數，並用 Excel 開啟含危險前綴答案及無提交題目的匯出 CSV。

## Risks / Trade-offs

- [略過範圍判斷錯誤而吞掉有效題目] → 只有下一個可正規化題號才結束略過狀態；警告標示無效題號位置；加入涵蓋後續列的解析測試。
- [Socket disconnect 回呼期間仍可在連線清單看到該 Socket] → 聚合時計入 `connected` 狀態，並以連線生命週期測試確認數量最終更新。
- [CSV 加單引號改變原始欄位文字] → 僅對指定前綴生效，保留既有 CSV quoting 與未匹配資料內容。
- [無提交佔位列被誤認為實際提交] → 只在說明欄明確標記「沒有組別送出」，其他空值欄位保持空白。

## Migration Plan

不需資料遷移：組數及連線計數皆在活動執行期驗證或計算。部署後重啟即由新程式建立視圖；如需回復，回退程式版本即可，既有題目集、回寫資料及備份格式不變。

## Open Questions

無。組數範圍、連線數統計口徑、CSV 欄位規則及佔位列欄位已由需求明定；佔位列採每題一列並保留題號。
