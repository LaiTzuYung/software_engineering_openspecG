# Design

## Context

老師登入頁、老師控制台與學生頁由 `src/live-buzzer/pages.ts` 的 HTML 字串提供，頁面樣式內嵌，互動使用既有 DOM selector 和事件監聽器。老師匯入預覽已使用 DOM 表格呈現。學生狀態的 HTTP、Socket 初始／更新／查詢／重連都共用 `createStudentView` 白名單；本 change 只在既有 view 新增本組已提交答案欄位。準備中與搶答中仍不含他組資料或結果；活動結束時原有每題成功組名稱與成功答案結果照常提供。需求見 proposal.md 與 specs/live-buzzer/spec.md。

## Goals / Non-Goals

**Goals:**

- 以純 CSS 和最小 HTML/class 調整，建立深色、限寬、卡片化且適合投影閱讀的登入頁、老師頁與學生頁；老師與學生主內容共用最大寬度並置中。
- 讓三種階段徽章、按鈕用途、提交／錯誤狀態、老師端結果及回寫預覽狀態有一致且清楚的視覺區分。
- 以 DOM 表格呈現老師匯入預覽摘要、警告與逐小題位置，並提供收合的原始 JSON 檢視。
- 加入老師敘述設定的大型點擊控制，以及學生已送出題目的收合式本組答案檢視。
- 在 HTTP 與 Socket 的學生視圖白名單加入本組已提交答案；搶答結束前維持資料隔離，結束後保留既有成功組與答案結果。
- 維持現有自動測試 selector 及 DOM ID、按鈕文字與操作流程。

**Non-Goals:**

- 不調整 API 路由、Socket.IO 事件名稱、確認匯入流程或儲存模型。此 change 唯一超出外觀修改的例外是學生 DTO 白名單新增本組提交答案，讓學生可核對本組答案；此新增欄位在任何階段都只讀取目前 groupId。保留既有活動結束後學生可檢視每題成功組與成功答案的結果行為。
- 不增加框架、外部字型、CDN 或其他網路載入資源。

## Decisions

- 在登入、老師與學生頁的內嵌樣式中使用一致 CSS 變數統一背景、表面、文字、邊框、主色、成功色、警告色與危險色，避免新增建置流程或依賴；登入頁沿用學生頁的中央卡片與按鈕語彙。
- 老師與學生頁採相同 `82rem` 外層最大寬度及置中的 `main`；學生的加入表單與題目卡片由置中的主容器承載，避免寬視窗時偏左。
- 對既有狀態元素加語意 class 或包裝結構，並以資料階段對應樣式；保留既有 ID 與原有 class/selector，新增 class 不覆蓋舊 selector。
- 使用既有匯入預覽欄位在前端建立摘要、警告清單、逐小題資料列及 `<details>` 原始 JSON。以 `textContent` 建立動態文字，題組每個小題各列一筆，描述由 CSS 截斷；來源使用既有 `importSource` 判斷 Google 試算表或 XLSX。保持 `#import-preview`、預覽 API 回應和確認匯入事件不變。
- 匯入預覽表格使用固定欄位配置並填滿外層容器，題目敘述欄配置剩餘寬度，窄螢幕則保留水平捲動。
- 將 `#descriptions` 包在具備較大點擊範圍的既有 label，放大 checkbox 並加強勾選色彩；不更動其 ID 或 change handler。
- 學生 view 的每個小題只在該本組已有提交時帶入該小題答案；所有學生傳輸仍呼叫同一個明確白名單建構器。搶答前與搶答中 `results` 為 `null`；活動結束時照舊提供每題成功組名稱與成功答案。
- 已送出題卡在「本組已送出」之後呈現預設收合的 `<details>`，展開逐小題讀取本組答案。結束階段同時呈現本組答案與既有 `results`。
- 新增 view 單元測試與 HTTP／Socket 整合測試：同題兩組都提交後，驗證搶答中不含他組資訊；結束後驗證 `results` 與既有成功組／答案一致，並獨立確認 `questions` 中的本組答案欄位只含本組答案。保留既有四通道 R9 測試。
- 表格採深色表面與一致表頭樣式，長表格表頭可 sticky；成功格、順位、答案及預覽狀態以文字加顏色呈現，確保顏色不是唯一辨識線索。
- 按鈕依現有行為和文案套用主要、危險、次要及停用樣式；僅以 CSS 呈現，不改變 disabled 條件或按鈕文字。
- 保持基礎字級至少符合大型投影的易讀需求，透過容器限寬、彈性表格溢位及小螢幕媒體規則維持窄視窗可用。
- 不採用 UI 框架或外部 CSS：此頁面為伺服器直接輸出的離線可用頁面，內嵌樣式最符合現有架構。

## Risks / Trade-offs

- [新增 class 或包裝元素可能影響測試依賴的 DOM 結構] → 先核對 `tests/live-buzzer-views.test.ts` 及其餘相關測試所依賴的選擇器，保留既有 ID、按鈕文字與 class，並以 `npm test` 驗收。
- [高密度老師表格在投影上可能過寬] → 允許表格水平捲動，保持表頭與每組答案的對應可讀。
- [顏色對比或階段樣式在不同畫面上不夠明顯] → 同時使用徽章文字、形狀/邊框與色彩，並依 tasks.md 逐頁、逐階段人工截圖檢查。
- [新增本組答案時意外洩漏他組資料] → `src/live-buzzer/views.ts` 新增的本組答案欄位只取目前 groupId 的已提交答案；所有傳輸路徑仍透過單一白名單建構器，並在 buzzing／ended 狀態獨立檢查本組答案欄位。活動結束的既有 `results` 僅包含每題成功組與成功答案，不包含順位或提交序號。
- [匯入預覽欄位遺漏或文字被當成 HTML] → 只消費既有預覽物件欄位，以 DOM `textContent` 顯示；人工檢查單題、題組、警告及原始資料展開狀態，並跑完整測試。
- [加入本組答案後可能意外擴大學生 payload] → 只從指定 `groupId` 的 submission 建立本組答案欄位；搶答中斷言整體 payload 不含他組資料，結束後分別驗證本組答案欄位的隔離、既有成功組與答案 results，以及所有階段都不含順位／提交序號。

## Migration Plan

不變更路由、事件名稱或持久化資料。學生 view payload 增加本組答案欄位，學生端活動結束後每題成功組與答案的既有結果照常顯示。修改完成後執行 `npm test`，再依 tasks.md 人工檢視老師與學生頁在準備中、搶答中及已結束狀態的截圖；若呈現造成可用性問題，可回退頁面 HTML/CSS／DOM 組裝變更，無需資料還原。
