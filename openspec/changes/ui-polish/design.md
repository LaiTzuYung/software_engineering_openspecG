# Design

## Context

老師與學生頁由 `src/live-buzzer/pages.ts` 的 HTML 字串提供，頁面內含 CSS，並透過既有 DOM selector 和事件監聽器處理互動。學生頁建立題目內容時使用既有 class；老師頁以固定 ID 定位控制項，表格則由既有渲染程式動態建立。既有 97 個自動測試和學生 DTO 白名單是相容性邊界。需求見 proposal.md 與 specs/live-buzzer/spec.md。

## Goals / Non-Goals

**Goals:**

- 以純 CSS 和最小 HTML/class 調整，建立深色、限寬、卡片化且適合投影閱讀的兩頁樣式。
- 讓三種階段徽章、按鈕用途、提交／錯誤狀態、成功結果及回寫預覽狀態有一致且清楚的視覺區分。
- 維持現有自動測試 selector 及 DOM ID、按鈕文字與操作流程。

**Non-Goals:**

- 不調整伺服器 DTO、API、Socket.IO 事件、JavaScript 事件處理或學生 R9 白名單。
- 不增加框架、外部字型、CDN 或其他網路載入資源。

## Decisions

- 在兩頁各自的內嵌樣式中使用 CSS 變數統一背景、表面、文字、邊框、主色、成功色、警告色與危險色，避免新增建置流程或依賴。
- 對既有狀態元素加語意 class 或包裝結構，並以資料階段對應樣式；保留既有 ID 與原有 class/selector，新增 class 不覆蓋舊 selector。
- 表格採深色表面與一致表頭樣式，長表格表頭可 sticky；成功格、順位、答案及預覽狀態以文字加顏色呈現，確保顏色不是唯一辨識線索。
- 按鈕依現有行為和文案套用主要、危險、次要及停用樣式；僅以 CSS 呈現，不改變 disabled 條件或按鈕文字。
- 保持基礎字級至少符合大型投影的易讀需求，透過容器限寬、彈性表格溢位及小螢幕媒體規則維持窄視窗可用。
- 不採用 UI 框架或外部 CSS：此頁面為伺服器直接輸出的離線可用頁面，內嵌樣式最符合現有架構。

## Risks / Trade-offs

- [新增 class 或包裝元素可能影響測試依賴的 DOM 結構] → 先核對 `tests/live-buzzer-views.test.ts` 及其餘相關測試所依賴的選擇器，保留既有 ID、按鈕文字與 class，並以 `npm test` 驗收。
- [高密度老師表格在投影上可能過寬] → 允許表格水平捲動，保持表頭與每組答案的對應可讀。
- [顏色對比或階段樣式在不同畫面上不夠明顯] → 同時使用徽章文字、形狀/邊框與色彩，並依 tasks.md 逐頁、逐階段人工截圖檢查。
- [視覺整理意外改動學生 payload] → 不改 `src/live-buzzer/views.ts` 或任何資料建構邏輯，保留現有 R9 測試並在實作檢查白名單資料未變。

## Migration Plan

無資料或 API 遷移。修改完成後執行 `npm test`，再依 tasks.md 人工檢視老師與學生頁在準備中、搶答中及已結束狀態的截圖；若樣式造成可用性問題，可回退頁面 HTML/CSS 變更，無需資料還原。
