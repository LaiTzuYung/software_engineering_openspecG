# Design

## Context

目前專案是 Node.js 22／TypeScript，既有匯入流程由 `createPreviewFromInput` 產生預覽，再由 `GuidedNotesImportService.confirm` 將確認題目集寫入 `data/guided-notes/<id>.json`。CLI 尚無 HTTP 介面，也沒有活動伺服器；詳見 proposal.md 的範圍及 `specs/live-buzzer/spec.md` 的行為契約。

## Goals / Non-Goals

**Goals:**

- 在單一本機 Node.js 程序提供老師頁、學生頁、HTTP 端點及 Socket.IO 即時事件。
- 讓學生端所有通道在活動結束前回傳最小必要資料，保證不會接觸其他組答案或順位。
- 以伺服器收到順序原子地接受提交與配置每活動序號。
- 保留現有匯入服務為預覽和確認的唯一實作來源。

**Non-Goals:**

- 不提供程序重啟後的活動／作答復原，也不加入資料庫或跨裝置部署。
- 不實作答案回寫、CSV、公平機制、判錯遞補、倒數、大螢幕或 XLSX 備援；依 proposal.md 留給後續 change。

## Decisions

### 單一程序與頁面

使用 Node.js HTTP server 提供靜態老師／學生 HTML、必要的 JSON API，並在同一 server 掛載 Socket.IO。頁面由原生 HTML、CSS 與少量 JS 實作，不引進前端框架；即時畫面更新使用 Socket.IO 事件。此方式符合單機、一指令啟動及本次兩種角色的需求，避免額外建置前端 bundle 或第二個服務。

### 活動與題目集資料

活動、分組、階段、記憶體工作階段及提交事件只存在程序記憶體；重新啟動後皆歸零。題目集仍由 `data/guided-notes/` 的 JSON 讀取，確認匯入時繼續使用既有 `GuidedNotesImportService` 寫檔。活動建立時載入指定題目集的不可變快照，避免活動中途題目集內容變動影響題目與順位。

題目集清單由伺服器列舉該目錄下的 JSON 並驗證必要欄位，再交老師選擇。既有 import-service 目前有解析預覽與確認 API，但沒有目錄清單 API；清單讀取屬於活動伺服器邊界，不重寫匯入解析或持久化流程。

### 活動代碼、組別與老師 PIN（待與 SpecKit 組對齊）

本次先以單一活動記憶體狀態實作，建立時產生四位數字活動代碼。因同時僅有一個活動，無須處理活動代碼碰撞後的多活動選擇；新活動取代舊活動前需通過老師控制流程。組數與組名在建立時指定，預設四組「第 1 組」至「第 4 組」，組名建立後不可修改。

老師 PIN 從環境變數讀取；未設定時由程序啟動時隨機產生，僅於本機 server 啟動輸出一次供老師使用。PIN 不放在學生頁或學生端 API。此預設和活動代碼格式、單活動限制、組名可否修改均列於本節待與 SpecKit 組對齊。

### HTTP 匯入介面

老師頁呼叫 HTTP 預覽與確認端點。預覽端點沿用既有 `createPreviewFromInput`／`GuidedNotesImportService.preview`；確認端點沿用同一服務實例的 `confirm(previewId)`。伺服器程序共享一個匯入服務實例，讓待確認 preview 在兩個 HTTP 請求間保留。未確認預覽只在記憶體，不建立題目集；確認後仍按既有行為寫 JSON。HTTP 回傳既有預覽結構與匯入錯誤，不另造解析規則。

### 提交資料模型與原子性

每個活動保存階段、題目快照、組別、全活動遞增序號，以及按題目和組別索引的接受提交。全活動遞增序號保留作為內部排序依據；對外顯示與後續 CSV 的「順位」是各題內依序號排序後的名次（1、2、3…），每題各自從 1 起算。題組以整題為單位計算順位，同組各小題顯示相同順位。提交請求先檢查角色／活動階段／題號與小題／答案內容／題組完整性／該組是否已有答案；全數通過後才一次寫入相關小題提交。拒絕請求不得產生部分答案或序號空洞。

提交 handler 的驗證、檢查重複、取得下一序號與寫入接受提交必須在同一個同步的 JavaScript 呼叫區段完成，中間不得 `await`、排程 callback 或發出 Socket 事件。Node.js 單執行緒 event loop 會讓該同步區段完成後才處理下一個請求，因此兩組同時到達時會得到明確的伺服器處理順序；同組競爭時第一個完成該區段的請求會佔有唯一提交位置。通知 Socket.IO 的非同步工作在資料寫入後執行，不參與判定。

本次暫定答案驗證為移除所有空白後，以 Unicode code point 計數；單題上限 200，題組按每個小題各自 200。空白判斷也以移除空白後是否為空字串為準。此計數口徑列待對齊。

### R9 學生資料最小化

建立獨立的學生 DTO／序列化邊界：只輸出活動代碼、目前階段、學生所屬組別的已送出狀態、允許顯示的題號／敘述，以及活動結束後公開的每題成功組與答案。學生 DTO 不從完整老師狀態複製後再刪欄位，而由明確白名單欄位組成；老師 DTO 才包含各組答案與順位。

HTTP 狀態、加入活動、Socket 初始快照、重連快照與後續廣播均呼叫同一學生序列化邊界。提交廣播只送組別已送出狀態給學生；答案與順位只向老師 namespace／room 發送。活動結束前成功組及答案亦不送給學生；切換為已結束後，學生端結果快照才附上每題成功組與答案。

每個端點和 event payload 測試直接檢查伺服器輸出的 JSON 物件，使用他組含辨識性答案與順位的測試資料確認內容不存在；只驗證頁面隱藏不視為通過。

### 階段、Socket 與 D8

階段轉移只允許準備中至搶答中，以及搶答中至已結束；老師 HTTP 控制操作先更新記憶體狀態，再廣播最小階段 DTO。學生連線、重新連線及 HTTP 狀態查詢都從同一份目前記憶體狀態建立快照，加入中途不依賴先前事件歷史。

題目敘述顯示設定存活動記憶體狀態，預設關閉；老師可隨時切換。切換事件即時更新學生題目顯示 DTO。結束後的學生結果只包含每題成功組及答案，此為本 change 的暫定預設。

## 待與 SpecKit 組對齊

以下均是本 change 按使用者指定採用的預設，並非共同需求基準已定義內容：

- 老師 PIN 使用環境變數；未設定時隨機產生，啟動時輸出一次。
- 活動代碼為四位數字，同時間只存在一個活動。
- 答案移除空白後按 Unicode code point 計數；題組按每小題各自計算 200 字上限。
- 提交序號在每個活動內遞增。
- 活動結束後學生可檢視每題成功組與答案。
- 組名建立活動後不可修改。
- 老師可在活動期間隨時切換學生是否顯示題目敘述。
- 支援 Chrome 最新版，介面使用繁體中文。

## Risks / Trade-offs

- [R9 若任何新 API 或事件漏接白名單序列化，可能洩漏他組答案] → 所有學生讀取通道共用學生 DTO 建構器；逐通道測試實際伺服器輸出，並以秘密測試答案斷言 payload 不含他組資料。
- [記憶體活動在程序重啟後消失] → 啟動時明確顯示目前沒有活動；此為本次指定行為，不做復原。
- [Socket 廣播失敗而狀態已接受] → 伺服器狀態為權威資料，重新連線／狀態查詢由當前快照補齊；廣播不回滾已接受提交。
- [Google Sheets 匯入預覽是非同步請求，預覽確認可能延遲] → pending preview 維持在共享 import-service 記憶體；程序重啟後需重新匯入預覽。
- [四位數代碼及單活動限制不適合多班級並行] → 將限制明列為待對齊預設，後續需求若改變再擴充活動索引與代碼策略。

## Migration Plan

新增單一伺服器啟動入口及 Socket.IO 相依套件，以一個 npm 指令啟動本機服務；不遷移既有題目 JSON。啟動後活動狀態為空，老師可從既有題目集建立新活動。回退時停止新伺服器入口即可；不需清理活動資料，因活動與提交只存在記憶體。
