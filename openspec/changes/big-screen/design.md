# Design

## Context

目前 `views.ts` 以白名單建立學生與教師視圖：學生視圖只含本組答案，教師視圖含所有組的提交明細、順位和答案。Socket.IO 目前辨識 `teacher`、`student` 與未授權連線；學生提交只推播給同組，並更新教師視圖。HTTP 狀態路由也使用各自的視圖建構器。活動模型同時只有一個活動。排名計算已提供每題原始順位、最終順位、成功與跳過狀態。

詳見 [proposal.md](proposal.md) 的動機與 [specs/big-screen/spec.md](specs/big-screen/spec.md)、[specs/live-buzzer/spec.md](specs/live-buzzer/spec.md) 的行為契約。

## Goals / Non-Goals

**Goals:**

- 讓公開大螢幕 HTTP 與 Socket 傳輸都只能取得明確定義的 screen view。
- 讓準備中、搶答中與已結束的欄位在 DTO 結構上有階段界線。
- 讓已結束的學生結果顯示成功答案及其他組順位，同時隱藏其他組答案。
- 繼續讓搶答中學生不因新增結果欄位而取得任何他組資訊。

**Non-Goals:**

- 增加倒數計時、活動切換、第二個同時活動或大螢幕操作控制。
- 改變順位計算、成功組判定或均分上限規則。

## Decisions

### 使用獨立的大螢幕視圖建構器

在 `views.ts` 新增專用 screen view 型別與建構器，明確複製必要欄位，不序列化 `ActivityState`，也不轉用教師或學生視圖。準備中只提供活動代碼、組數、排名規則、題目摘要及等待狀態；搶答中每題只提供已提交組數與總組數；已結束才附結果欄位。

**替代方案：**從教師視圖刪除欄位後供大螢幕使用。這會使安全性依賴刪除清單是否完整，未來教師視圖新增欄位也可能意外外洩，因此採獨立白名單。

### Screen 角色只讀並使用專用傳輸

Socket 授權資料辨識 `role: "screen"`，此角色只接收 `activity:screen-view`，並由伺服器拒絕所有改變活動狀態或提交答案的事件。HTTP `/api/screen/state` 使用同一 screen view 建構器；`/screen` 頁本身公開且不要求登入。活動建立、階段轉換及成功提交時，伺服器更新連線中的 screen sockets。這也確保提交推播範圍維持為提交組、教師與大螢幕，不向其他學生推播。

**替代方案：**讓瀏覽器輪詢狀態端點。這會延遲數字更新並增加重複請求；採 Socket 推播並以 HTTP 回應提供初始載入狀態。

### 搶答期間以數量而非明細呈現

每題已送出數以該題已接受提交的組數計算，總組數取活動設定組數。screen DTO 在 `buzzing` 階段不建立 results 或 submission 清單，因此答案、組名、順位與成敗資訊不會只靠頁面隱藏。

**替代方案：**傳送全量結果後由前端計數。這會把不應公開的資料送至投影裝置，不符合伺服器端隔離，因此不採用。

### 學生結果只輸出成功答案與其他組的原始順位

以排名計算器的每題提交結果建立學生 ended results：成功組沿用既有成功組和小題答案；其餘提交僅輸出組名、原始順位與是否因均分上限被跳過。被跳過者顯示「已達上限（跳過）」且最終順位不提供。其他提交答案、內部 sequence 與非必要排名欄位均不進入學生 DTO。原始順位用來呈現實際送出先後；design 固定此選擇，即使均分上限令最終順位不同。

**替代方案：**顯示套用均分上限後的最終順位。跳過提交沒有最終順位，且遞補後的名次不代表各組實際提交先後；依需求採原始順位。

### 投影頁沿用深色樣式並放大資訊層級

新增獨立大螢幕頁面與渲染流程，沿用 ui-polish 的深色配色、卡片與階段視覺語彙；活動代碼、送出數及答案採較大字級，階段以徽章標示。瀏覽器端只顯示其 DTO 已提供的欄位。

**替代方案：**直接套用學生頁版面。學生頁密度與輸入控制不適合投影，故建立專用版面並沿用樣式語彙。

## Risks / Trade-offs

- [Screen 初始 HTTP 與 Socket 更新可能競速] → 兩種傳輸使用同一建構器，頁面以最新收到的階段視圖重繪，並測試初始載入與提交更新。
- [新增結果欄位可能破壞 R9] → 搶答中維持 `results: null`，且對 HTTP、Socket、查詢、重連持續執行既有隔離測試。
- [公開投影頁可能在結束前暴露答案] → Screen role 的 buzzing DTO 不含結果型別欄位，HTTP 與 Socket 測試均檢查答案、組別明細、順位與成敗資訊不存在。

## Migration Plan

不需資料遷移。新增 HTTP 路由、screen Socket role 與 `/screen` 頁後，舊有老師及學生連線維持各自視圖。回退時移除大螢幕端點與推播，以及學生 ended result 新欄位即可；活動資料格式不變。
