# Proposal

## Why

目前活動與學生身分只存在伺服器記憶體，程序重啟會丟失進行中的課堂狀態，與共同需求基準 v0.7 的 D12 不符。老師與學生必須能在重啟後回到原活動、階段、組別及已送出的內容，讓課堂可以繼續或正常結束。

## What Changes

- 將目前活動快照持久化至 `data/` 下 JSON，包含建立時題目集副本、設定、已接受提交、下一序號及學生 sessionToken 對組別的對應。
- 每次活動狀態改變均先完成依序安全存檔，再推播；啟動時驗證並恢復快照，排名與成功組從提交重算。
- 學生分頁以 `sessionStorage` token 重連並回復原組、畫面及本組答案；重啟後線上頁面數從零重新計算。
- 固定 `TEACHER_PIN` 沿用並由老師頁工作階段自動重連；未設定時每次啟動產生新 PIN，舊 PIN 失效並要求重新登入。
- 無效或損壞活動檔記錄錯誤後以沒有活動啟動，保留原檔供檢查；回寫原值備份沿用現行機制。
- 更新老師畫面及 README 的持久化說明；回寫預覽快照仍只在記憶體，重啟後須重新預覽。
- 明確記錄單一活動限制：建立新活動會取代舊活動檔；D12 的「所有活動」在此系統意指目前唯一活動。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `live-buzzer`: 活動、提交與學生工作階段在伺服器重啟後持續存在並恢復；老師驗證依固定或隨機 PIN 規則重連。
- `result-export`: 回寫備份在活動重啟後仍可供原值還原；回寫預覽快照不持久化，需重新建立。

## Impact

- 主要影響 `src/live-buzzer/model.ts`、`submissions.ts`、`http-server.ts`、`socket-server.ts`、`pages.ts`、匯出備份服務與其 HTTP／Socket／頁面測試。
- 使用既有 `data/` 本機資料目錄，不新增外部依賴；資料檔需有版本與嚴格格式驗證。
- 增加以同一暫存資料目錄建立第二個伺服器的重啟整合測試，以及 Ctrl+C 人工恢復流程。
