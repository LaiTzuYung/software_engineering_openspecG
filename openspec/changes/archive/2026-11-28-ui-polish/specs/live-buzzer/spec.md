# Spec Delta

## ADDED Requirements

### Requirement: 階段與結果狀態可視辨識
老師頁與學生頁 SHALL 以一致且易辨識的視覺樣式呈現活動階段、成功組、提交狀態及操作訊息。

#### Scenario: 三種活動階段使用不同徽章
- **WHEN** 老師或學生頁顯示準備中、搶答中或已結束階段
- **THEN** 各階段以彼此可區分且兩頁一致的徽章樣式呈現

#### Scenario: 成功組醒目呈現
- **WHEN** 老師表格或老師結束結果頁顯示題目成功組
- **THEN** 成功組與答案以明顯的成功樣式呈現，且易於與其他組別或一般內容區分

#### Scenario: 已送出狀態明顯呈現
- **WHEN** 學生所屬組別已送出題目答案
- **THEN** 頁面以醒目樣式顯示本組已送出，並與錯誤訊息採用不同樣式

## MODIFIED Requirements

### Requirement: 老師頁提供既有題目匯入介面
系統 SHALL 透過老師頁提供既有 Guided Notes 匯入服務的預覽與確認流程，且確認前不得建立題目集。

#### Scenario: 老師預覽並確認匯入
- **WHEN** 已驗證老師提交試算表匯入請求並檢視預覽
- **THEN** 老師可透過 HTTP 介面確認匯入，並由既有匯入服務建立題目集

#### Scenario: 未確認匯入不建立題目集
- **WHEN** 老師完成匯入解析但尚未確認預覽
- **THEN** 題目集不會建立，老師頁提供預覽內容及確認操作

#### Scenario: 老師預覽匯入時以表格呈現題目與作答格
- **WHEN** 老師完成匯入預覽並檢視題目內容
- **THEN** 預覽以逐小題表格顯示題號、類型、小題、標籤格、作答格及題目敘述，並在摘要顯示工作表名稱、來源、總題數、單題數與題組數，警告醒目可辨；原始 JSON 預設收合

### Requirement: 結束前隔離其他組作答資料
所有學生狀態 HTTP 回應與 Socket.IO 事件在活動結束前 SHALL 不包含任何他組作答答案、提交內容、組別身分或順位；學生視圖新增的本組答案欄位在任何階段 SHALL 只包含該學生所屬組別已提交的答案。活動結束後 SHALL 保留既有每題成功組名稱與成功答案的 `results` 行為，且不得在順位或本組答案欄位中混入他組資料。

#### Scenario: HTTP 學生狀態回應不含他組作答
- **WHEN** 學生在準備中或搶答中，以 HTTP 查詢其活動狀態或作答狀態
- **THEN** 回應只包含該學生所屬組別的提交狀態與已提交答案，不含他組答案、提交內容、組別識別資訊、結果或順位

#### Scenario: Socket 事件不含他組作答
- **WHEN** 活動尚未結束時，學生訂閱或接收階段、提交、更新或狀態 Socket 事件
- **THEN** 每個伺服器送出的學生視圖 payload 只包含該組可見狀態與本組答案，不含他組答案、提交內容、組別識別資訊、結果或順位

#### Scenario: 他組提交不觸發本組任何推播
- **WHEN** 第 1 組送出答案
- **THEN** 第 2 組連線不得收到該提交訊息，只有第 1 組連線收到更新；階段變更與題目敘述開關仍推播給所有學生

#### Scenario: 學生重連不取得他組作答
- **WHEN** 活動尚未結束時，學生端斷線後重新連線
- **THEN** 伺服器回應只包含該學生所屬組別的狀態及本組已提交答案，不含任何他組資料、結果或順位

#### Scenario: 狀態查詢通道不洩漏他組作答
- **WHEN** 活動尚未結束時，學生呼叫支援的狀態或快照查詢通道
- **THEN** 回傳 payload 只包含該組可見狀態及本組答案，不含他組答案、提交內容、組別識別資訊、結果或順位，且此條件由自動測試驗證

#### Scenario: 學生可查看本組已送出的答案
- **WHEN** 第 1 組與第 2 組均已提交同一題，且第 1 組學生於活動進行中或已結束時讀取學生視圖
- **THEN** 新增的本組答案欄位只包含第 1 組已送出的答案，不包含第 2 組答案、組別識別資訊、順位或任何其他組資料

#### Scenario: 結束後學生檢視結果
- **WHEN** 活動已結束時，學生檢視活動內容
- **THEN** 學生可查看既有每題成功組名稱與成功答案；新增的本組答案欄位仍只包含本組已提交答案，且結果不包含順位或提交序號
