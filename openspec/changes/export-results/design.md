# Design

## Context

See [proposal.md](proposal.md) for the motivation and scope. 匯入題目集目前保存工作表名稱與 answerCell/labelCell 座標，但不保存試算表 ID/gid；Google adapter 僅使用唯讀 scope。活動提交以題號和組別保存答案與遞增序號，沒有送出時間，活動狀態只在程序記憶體中。

## Goals / Non-Goals

**Goals:**

- 重用既有解析器與成功組／順位邏輯，並以預覽確認與結構比對保護回寫目標。
- 讓 Google 試算表批次回寫、可選擇性還原，以及 CSV 匯出可由服務端單元測試驗證。
- 顯示實際資料限制：XLSX 來源不可回寫，程序重啟會遺失活動結果。

**Non-Goals:**

- 活動、題目集與提交的程序重啟持久化。
- 公平順位、判錯遞補或非成功組答案回寫。
- 將 XLSX 離線修改後再下載。

## Decisions

### 保存來源與提交時間

在解析 Google URL 時把 spreadsheet ID 與明確的 gid（網址有指定時）附加到匯入預覽和已確認題目集；預設工作表來源需保存其 sheetId，避免未指定 gid 時日後改變第一張工作表而回寫錯表。XLSX 題目集來源欄位為空。提交接受時由伺服器產生一個 ISO 8601 timestamp，放在整筆 `AcceptedSubmission` 上；題組小題輸出時共用此值。

### 共用解析器並以穩定識別鍵比對

回寫預覽及確認都使用來源 ID 讀取 Google 表格並呼叫既有 Guided Notes parser。以題號及小題號作為身份鍵，比對完整題目／小題集合、單題或題組分類、answerCell 座標及 labelCell 座標。重新解析失敗、集合不完整或座標不同時整批中止。不同 gid、來源 ID 或工作表識別也視為錯誤。

預覽保存伺服器端短期快照，內容包含活動識別、來源、解析結構指紋、每個目標格的目前原始值、預計寫入答案、座標及預覽時間。確認使用預覽 ID；伺服器重讀並重算結構和目標值，只有與快照完全一致才繼續。預覽 ID 不得由客戶端傳回的座標或寫入值取代，並在成功使用後失效，防止竄改與重放。若服務重啟，預覽自然失效。

### 寫入與備份順序

建立寫入清單時只納入每題成功組的所有小題，使用重新定位後的 answerCell；不納入 labelCell 或題目儲存格。`目前內容 == 預計寫入值` 的格子標示「內容相同略過」，其餘格子在預覽清楚呈現覆蓋值。老師確認即授權覆蓋預覽中的格子。

確認時依序：讀取與比對、建立含原值和目標值的唯一 JSON 備份、呼叫一次 Google Sheets `values.batchUpdate` 並指定 `RAW`。若所有目標值都相同，不發 API 寫入，也不建立新的回寫備份。API 寫入失敗時不自動重試、不進行失敗後重新讀取；回報錯誤訊息與備份檔位置，並將該次備份標記為失敗。服務帳戶缺少編輯權限時，錯誤訊息須說明將試算表共享給服務帳戶並設為編輯者；讀取權限不足則使用不同的讀取錯誤訊息。只有確認成功的回寫紀錄才成為「最近一次成功回寫」，失敗備份不改變此紀錄。

還原最近一次成功回寫時，逐格重新讀值。僅當目前值等於備份中的寫入值，才把原值放入 RAW 還原批次；其他格逐一略過並回報。最近一次成功回寫不因後續失敗嘗試而改變。若沒有成功回寫紀錄，還原操作回報明確結果。

### 結果與 CSV

每個已接受 submission 產生一筆 CSV 小題列。各題呼叫既有 question-local ranks；最終順位複製原始順位，成功欄依每題成功組判斷，說明留空。使用 RFC 4180 相容欄位跳脫（雙引號加倍，必要時以雙引號包住欄位），並輸出 UTF-8 BOM。`submittedAt` 由伺服器接受提交時生成，不讀客戶端時間。

### API 與 UI 邊界

在已驗證老師 API 增加回寫預覽、確認回寫、最近一次還原及 CSV 下載端點。所有動作由服務端檢查 stage 為 `ended`。老師頁以預覽表格呈現 A1、目前值、預計值、狀態；確認按鈕提交預覽 ID。只有已保存 Google 來源的題目集顯示回寫入口；CSV 只要活動結束即可使用。

將 scope 改為 `https://www.googleapis.com/auth/spreadsheets`，且 adapter API 型別擴充 `values.batchUpdate` 與對指定格讀值能力。保留 API client 工廠注入方式，測試使用 mock，不呼叫真實 Google API。

## Risks / Trade-offs

- [Google API 寫入失敗或逾時時，伺服器不自動確認遠端是否部分套用] → 將備份標記為失敗，回報錯誤與備份位置；老師可檢查試算表後自行決定後續操作，不自動重試或重新讀取。
- [同一時刻其他人可修改試算表；重新讀取到批次寫入之間仍有競態] → 預覽確認時再次核對，並縮短核對至寫入的時間；Sheets API 不提供跨讀寫交易鎖。
- [本機 `data/` 遺失會使備份無法還原] → README 說明需保留部署資料目錄；備份不含服務帳號憑證。
- [scope 擴大需要重新授權] → 在部署文件列出 scope 變更與重新授權步驟，對讀取／寫入權限錯誤提供明確訊息。
- [活動重啟遺失] → README 與老師頁清楚說明結果只在目前程序生命週期存在；持久化不在本 change 範圍。

## Migration Plan

1. 新增題目集來源欄位及 submission timestamp 欄位；舊題目集沒有來源資訊時仍可檢視活動與匯出既有資料，但不顯示試算表回寫。
2. 部署後更新服務帳號 OAuth scope 並重新授權，確認服務帳號對目標試算表有編輯權限。
3. 先用 T2 測試表驗證預覽、回寫、還原及 CSV；確認後才供老師用其他表格操作。
4. 回退程式時停止使用新回寫端點；已寫入的試算表可用備份 JSON 還原，舊程式不應刪除 `data/` 備份。
